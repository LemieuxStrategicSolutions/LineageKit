# LineageKit

**An operating system for serious family-tree research — run by you and your AI research partner.**

LineageKit is not a genealogy app. It is a *practice*, packaged so an AI assistant can install it for you: an evidence-first research methodology, a five-table data model with stable IDs, a research-cycle protocol, GEDCOM tooling, and a deployable public family-archive website — all wired together so a human hobbyist and an AI agent can do rigorous genealogy as partners without the tree turning into a pile of unsourced name matches.

> **The one instruction:** open this repo with your AI assistant (Claude Code, Codex, or any capable agent harness) and say:
> *"Read `BOOTSTRAP.md` in this repo and set this system up for me."*

This pattern runs in production: the reference implementation is a private research project covering eight ancestral lines, 975 seeded individuals, 340+ registered sources, and 24 completed research cycles, with a public family archive site deployed at the edge. This repo is that system with every personal fact removed — the machinery, none of the family.

## The core ideas

**1. Evidence labels, not vibes.** Every claim carries one of five statuses:

| Label | Meaning |
|---|---|
| **Confirmed** | Supported by strong, consistent evidence |
| **Probable** | Best explanation, but one important proof point is missing |
| **Hypothesis** | A research lead that has not been established |
| **Conflicting** | Credible sources disagree |
| **Disproved** | Evidence rules the claim out |

Hints, public trees, indexes, and name matches are *leads, not proof*. Nothing is promoted to confirmed on a name match alone.

**2. The working loop.** Each unit of research follows eight steps: pick one person, couple, branch, or mystery → state a precise research question → check existing data first → search records by place and time, not by name alone → save the record, the citation, and *what it actually proves* → update the structured data → write the human story only after the facts are stable → record the next unresolved question.

**3. Research cycles.** Work happens in numbered, bounded cycles, each with a charter (scope + governing question), a report (findings with explicit promote/don't-promote verdicts per line), and a position statement of what did and didn't advance. Restraint is recorded as a result, not a failure. See [`cycles/`](cycles/).

**4. Negative searches are data.** Knowing where a person was *not* found prevents repeating the work. The Research Log records failed searches with the same discipline as finds.

**5. Your commercial tree host stays read-only.** MyHeritage, Ancestry, FamilySearch trees — whatever you use — is reference material and (once) a GEDCOM seed source. This system never writes back. Your local evidence record is canonical.

**6. The AI carries the queue, not you.** "Hobby mode" is a contract clause: research questions, next searches, and follow-ups live inside the project and are worked by the AI research partner. They never become homework on the human's task list. Discoveries are surfaced conversationally.

## The public archive site

[`site/`](site/) is a deployable family-archive website (Next.js on Cloudflare Workers, D1 + R2): branch pages for each ancestral line, a research library rendering your cycle reports, a timeline, story pages, and a **family contribution inbox** — relatives can submit memories, photos, and documents through a moderated pipeline (honeypot, rate limiting, file screening, a private review queue).

Publication rule, enforced by an allowlist redaction manifest: deceased relatives and historic records may be published; **living people are never published** except as unnamed connecting generations. See [`docs/publishing-guide.md`](docs/publishing-guide.md).

## What this project will not do

- **It will not merge two people because their names match.** Identity requires an independent bridge: dates, places, relatives, occupations, records.
- **It will not write to your commercial tree host.** Ever. Read-only is a boundary, not a default.
- **It will not publish living people.** The published layer is allowlist-only.
- **It will not turn your hobby into a task list.** The queue belongs to the research partner.

## Privacy model

- **This repo:** generic forever. Every person in `examples/` and `site/` is invented; no real family data, ever.
- **Your repo:** private forever. BOOTSTRAP generates a *separate, private* research folder. Nothing flows back here.
